# 성분표 스캐너 (PWA)

과자·가공식품 뒷면의 원재료명을 찍으면, '첨가물 경계 목록' 31종과 대조해 한 줄 판정과 성분별 상세를
보여주는 설치형 웹앱. 사진은 기기 안에서만 처리됩니다(Tesseract.js 한글 OCR). 서버·API 키 없음.

## 파일
- `index.html` — 앱 전체(디자인·화면·전처리·OCR 호출·판정·인포그래픽)
- `additives.js` — 첨가물 데이터 + 성분표 표기 별칭 + 매칭 로직 (여기만 고치면 목록이 바뀝니다)
- `sw.js` — 오프라인 캐시. **파일을 고쳤으면 `VERSION`을 올려야** 설치된 앱이 갱신됩니다.
- `manifest.webmanifest`, `icons/` — 홈 화면 설치용. `icons/icon.svg`가 원본 일러스트
- `vendor/` — Tesseract.js 5 엔진, `tessdata/kor.traineddata` — 한글 인식 모델(tessdata_fast)

## 디자인 노트

**마크** — 조각케이크를 돋보기로 들여다보는 플랫 일러스트. 렌즈 안의 작은 막대들이 원재료명 한 줄 한 줄이고,
그 색이 그대로 판정 등급 색입니다. `icons/icon.svg` 한 파일이 원본이고 앱 안에서는
`<symbol id="mark">`로 헤더와 히어로에 재사용합니다.

**색** — 지면은 파스텔(크림 `#FBF7F4`, 라일락 `#EAEAFA`, 서피스 흰색), 데이터 색은 등급 3단계:
확립 `#CE3F63` · 재평가 `#B07018` · 근거 약함 `#0B87A8`, 브랜드 페리윙클 `#7B7FD4`.
등급 색은 명도대·채도·색약(CVD) 분리·배경 대비 검증을 통과한 값이고, 다크모드용 단계
(`#DD6178 / #B8832C / #2F9FC0`)는 어두운 지면에 맞춰 따로 골랐습니다. 색약 분리가 경계 구간(ΔE 7.4)이라
색만으로 등급을 나타내지 않도록 모든 항목에 등급 이름을 글자로 함께 붙입니다.

**인포그래픽** — 네 가지이고 모두 실제 인식 결과에서 나온 값입니다.

1. 판정 카드의 등급 누적 막대 — 개수라는 하나의 척도, 범례에 숫자를 직접 표기
2. **원재료 순서 지도** — 원재료명은 함량 내림차순으로 적으므로, 걸린 항목이 목록 몇 번째인지가 곧 함량 힌트입니다.
   막대 하나가 원재료 하나이고, 색 있는 막대가 경계 첨가물, 회색은 당·소금 같은 기본 성분
3. 각 성분 카드의 순서 미니바 (n번째 / 총 m개)
4. 글자 인식 신뢰도 게이지 — 낮으면 원문을 확인하라는 신호

폰트는 오프라인 동작을 위해 기기 기본 한글 서체를 씁니다(웹폰트 없음).

## 배포 (GitHub Pages)
1. 새 저장소를 만들고 이 폴더의 내용을 그대로 올립니다(폴더 구조 유지).
2. Settings → Pages → Source를 `main` 브랜치 `/ (root)`로 지정.
3. `https://<계정>.github.io/<저장소>/` 접속 → 브라우저 메뉴에서 "홈 화면에 추가".

HTTPS가 필요합니다(카메라·서비스 워커 조건). Netlify, Vercel, Cloudflare Pages도 동일하게 됩니다.
로컬 테스트: `python3 -m http.server 8080` 후 `http://localhost:8080`.

## 데이터 수정
`additives.js`의 `D` 배열에서 항목을 추가·수정합니다.
- `aliases` — 실제 성분표에 인쇄되는 표기 (띄어쓰기·기호는 무시하고 비교)
- `basic:true` — 판정에서 제외되고 '기본 성분'으로만 표시 (당·소금·팜유·아크릴아마이드)
- `generic:true` — 용도명·노출원처럼 확인이 필요한 항목 ("확인 필요" 배지)
- `not:/…/` — 오탐 방지 패턴 (예: 착향료를 착색료로 잡지 않도록)
